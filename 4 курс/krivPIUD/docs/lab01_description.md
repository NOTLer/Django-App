# Лабораторная № 1 — что сделано и зачем

## Какая была задача

Нужно было подготовить единое рабочее место для следующих лабораторных:
запустить PostgreSQL и pgAdmin в Docker, настроить Python с нужными библиотеками,
не хранить пароль в Git и написать небольшую программу, которая доказывает, что
Python действительно умеет работать с базой.

Смысл задания не просто в том, чтобы увидеть запущенный контейнер. Должна
работать вся цепочка: Python подключается к PostgreSQL, создаёт таблицу,
записывает данные и читает их обратно.

## Что реализовано

В `docker-compose.yml` описаны два сервиса. `postgres` — сама база данных, а
`pgadmin` — веб-интерфейс, в котором таблицы можно смотреть без командной
строки. Оба контейнера находятся в одной сети Docker, поэтому pgAdmin обращается
к базе по имени `postgres`. Для PostgreSQL добавлена проверка готовности. pgAdmin
запускается после того, как база уже способна принимать подключения, а не просто
после старта её контейнера.

Данные базы вынесены в том `pg_data`. Благодаря этому обычная остановка или
пересоздание контейнера не удаляет таблицы. Порт 5432 открыт для Python на
компьютере, а порт 5050 — для входа в pgAdmin через браузер.

Настройки лежат в `.env`, а сам файл добавлен в `.gitignore`. Это нужно, чтобы
логины и пароли не попали в удалённый репозиторий. В Git можно хранить только
`.env.example`: в нём показано, какие параметры нужны, но при реальном проекте
значения из примера заменяются своими.

В `requirements.txt` закреплены версии библиотек. SQLAlchemy создаёт подключение
и выполняет SQL-команды, `psycopg2-binary` является драйвером PostgreSQL,
Faker генерирует тестовые имена и адреса, `python-dotenv` читает `.env`, а pandas
понадобится для дальнейшей обработки табличных данных.

Скрипт `scripts/test_connection.py` сначала проверяет, что все настройки базы
заданы. Затем он подключается к PostgreSQL и создаёт таблицу
`lab01_healthcheck`, если её ещё нет. Перед вставкой таблица очищается, поэтому
скрипт можно запускать много раз и каждый раз получать ровно 10 строк, а не 20,
30 и так далее. Десять людей и адресов генерируются через Faker, записываются в
одной транзакции, после чего программа выполняет `SELECT count(*)`. Если любой
этап не сработает, будет показано понятное сообщение об ошибке.

## Как проверить результат

Сначала нужно скопировать `.env.example` в `.env`, запустить контейнеры и
установить зависимости по инструкции из `README.md`. Команда
`python scripts/test_connection.py` должна вывести число 10 и сообщение об
успешной проверке. В pgAdmin таблица будет находиться по пути
`course_db → Schemas → public → Tables → lab01_healthcheck`.

Итог первой работы — воспроизводимое окружение: другой человек может взять
проект, выполнить несколько команд из README и получить такую же базу и такой же
результат проверки.
